# Skill: 去AI味写作规范

## When to Use

写完博客/文章后的质检流程，或对已有AI辅助生成的文章做去模板化改写。适用于中英文。

## 元数据

- **类型**: BestPractice
- **适用场景**: 博客去AI味改写、写作风格质检
- **创建日期**: 2026-03-23

---

## 检测规则（Detection Rules）

按严重程度排序。每条规则含：模式描述、识别方法、阈值。

### D01: 翻译腔句式（最高优先级，中文专用）

中文文章读起来像英文直译。这是中文AI味的最大特征。

**识别模式：**
- "这不是关于X。而是关于Y。" ← "It's not about X. It's about Y."
- "让我们使其具体化" ← "Let's make it concrete"
- "考虑两个场景" ← "Consider two scenarios"
- "这改变了一切" ← "This changes everything"
- 过度使用代词"他们""它们""这些"（中文可省略主语）
- 英语语序 S+V+O 贯穿全文，缺乏中文自然的灵活语序
- "而不是""而不仅仅是" 高频出现 ← "rather than"

**阈值：** 全文累计 ≥5 处即需全面改写句式

### D02: 同义堆叠

同一观点在 3 句内用不同措辞重复。AI 生成时常见的"换种方式再说一遍"。

**识别模式：**
- 论点 → 解释 → 重申（三段式重复）
- "复利/可复用/可迁移/可复利" 概念词堆叠
- 段末和段首说的是同一件事

**阈值：** 同一段落或相邻段落中，同一论点出现 ≥3 次

### D03: 元信息注释

打破第四面墙，向读者解释文章结构本身。

**识别模式：**
- "为什么需要这个表格：..."
- "为什么需要这个图表：..."
- "**核心判断**：" "**核心洞察**：" 等标签式引导
- "这里有一个关键区分："

**阈值：** 出现 ≥1 次即删

### D04: 防御性框架

过度声明文章的边界和非目标，像在写学术论文的 scope。

**识别模式：**
- "这不是一篇X文章，而是一篇Y文章"
- "本文不做的事情：" 后接列表
- "边界声明" 独立章节
- 开头或结尾反复强调"我只讨论X"

**阈值：** 同一文章 ≥3 处防御性声明

### D05: 公式化过渡

段落之间用模板化连接词，而非逻辑自然衔接。

**识别模式：**
- "这就是为什么..."（高频）
- "这意味着..."
- "换个角度思考"
- "真正的问题是..."
- "这改变了一切"
- "让我们..."

**阈值：** 全文 ≥5 处

### D06: 过度对称

每组列表项数量、结构、长度高度一致，像生成的模板。

**识别模式：**
- A 有 3 条，B 恰好也 3 条
- 信号1/信号2/信号3 每个内部结构完全对称
- 正反对比中，两侧条目数量和措辞长度完美匹配

**阈值：** ≥2 处完美对称结构

### D07: 冗余可视化

同一内容在正文、表格、图表中重复出现。

**识别模式：**
- 正文已经说清楚，又用表格复述
- 表格内容和前后段落 ≥70% 重叠
- 一个概念同时有文字、表格、mermaid 图

**阈值：** 出现 ≥1 次即需合并

### D08: 讲义式结构

文章像教材目录，而非博客。

**识别模式：**
- "第一部分：开篇现象" "第二部分：优化视角" 式编号标题
- 每段开头先下定义再展开
- 段落结尾必有总结性金句

**阈值：** 全文主要标题都是编号+类别式

### D09: 升华式结尾

文章结尾用格言或宏大叙事收束，而非自然结束。

**识别模式：**
- "在AI时代..."
- "构建存活的系统"
- "你不是在X，你是在Y"
- 最后一段突然拔高到哲学层面

**阈值：** 结尾段含格言式句子

### D10: 缺乏作者声音

全文无第一人称、无个人经历、无情感色彩。读起来像教科书。

**识别模式：**
- 全文零"我"（中文）或零 "I" "my"（英文）
- 全文零具体个人经历
- 语气完全客观中立，无判断倾向

**阈值：** 全文无第一人称且无个人经历

## 处理规则（Treatment Rules）

每条对应一个检测规则。

### T01: 翻译腔 → 母语重写

不是逐句修改，是整段用中文重新想一遍。判断标准：这段话你会这么跟朋友讲吗？

- "这不是关于保守。而是关于理解复利是路径依赖的。" → "重点不是保守不保守，是复利跟路径有关。"
- "大多数人不选择他们的函数。他们继承它。" → "多数人从没主动选过自己在优化什么，用的都是继承来的默认值。"
- "考虑两个场景" → 直接写场景，不加"考虑"

### T02: 同义堆叠 → 保留最强一句

扫描相邻 3 句，如果说的是同一件事，保留表达最有力的一句，删其余。

### T03: 元信息 → 直接删除

删除所有 "为什么需要这个表格" "核心判断：" 等元标签。表格和图表自己会说话。

### T04: 防御性框架 → 缩为一句或删除

如果边界确实重要，用一句话嵌入正文。不要独立成段或成节。
- "这个框架只适用于已经脱离生存焦虑的人" — OK，一句话够了
- "本文不做的事情：" 后面跟 6 条 — 删除整段

### T05: 公式化过渡 → 删除或用具体逻辑连接

段落之间靠论证逻辑连接，不靠过渡句。如果删掉过渡句后上下文仍然连贯，就删。

### T06: 过度对称 → 打乱

允许不对称。A 有 3 条，B 可以只有 1 条。合并重复项，只保留有信息量的。

### T07: 冗余可视化 → 保留一种形式

正文和表格选一个。如果表格更清晰，删正文的复述；如果正文已经说清楚，删表格。Mermaid 图同理。

### T08: 讲义结构 → 自然标题

- "第五部分：方法失效机制" → "方法为什么会过期"
- "第一层：工具型执行者" → 直接用内容做标题
- 去掉编号式标题，用能引起好奇心的表述

### T09: 升华结尾 → 具体收束

用一个具体场景、一句个人体会、或直接结束。不要格言。
- "构建存活的系统。" → "我现在做每个投资决策前，先问一个问题：这会不会让我被迫退场？"
- 如果没有合适的具体收束，就在最后一个论点结束后直接停笔。

### T10: 注入声音 → 适度第一人称

在开头或关键转折处加入 1-2 句第一人称。不需要每段都有。
- "我在一次凌晨 oncall 之后开始想这个问题"
- "我自己踩过的坑是..."

## 附加风格规则（来自 COMMUNICATION.md）

这些规则始终生效：

1. **不用破折号**（——/—/--）。能拆两句就拆，能用冒号就用冒号
2. **不用"长出来/长出了"** 形容系统演化。用"逐步形成""演化为"
3. **避免否定句式**，改用正向陈述。"这不是X" → 直接说"这是Y"
4. **不滥用 bullet points**。论述用自然段落，列举才用列表
5. **不堆砌形容词**。用数据和逻辑说话
6. **不用填充词**。"好问题""让我们来看看""值得注意的是" 全删

## 质检门（Quality Gates）

改写完成后，按以下顺序验证：

### Gate 1: 翻译腔检查（中文专用）
随机抽 3 段朗读，是否像中文母语者说话？有没有"而不是""而不仅仅是"的英语语序残留？

### Gate 2: 重复度检查
全文搜索核心关键词（如"复利""生存""不确定性"），确认同一论点没有重复 ≥3 次。

### Gate 3: 元信息检查
搜索"为什么需要""核心判断""核心洞察""这里需要"，确认为零。

### Gate 4: 过渡词检查
搜索"这就是为什么""这意味着""这改变了""让我们"，确认 ≤2 处。

### Gate 5: 信息保真度
原文的核心论点是否全部保留？有没有在改写过程中丢失重要论证？

### Gate 6: 长度检查
改写后长度应为原文的 65%-85%。低于 65% 可能丢信息，高于 85% 可能没改够。

---

## 处理流程

1. 读取原文全文
2. 识别：按 D01-D10 逐条扫描，记录问题数量
3. 改写：按 T01-T10 处理，优先级 T01 > T02 > T03（翻译腔 > 重复 > 元信息）
4. 检查附加风格规则
5. 通过 6 个质检门
6. 输出完整改写版

## Explicit Non-Goals

- 不改变核心论点与结论
- 不增加新观点或论证
- 不改变 YAML frontmatter 中的 title/date/tags/categories（但可以微调 title 措辞）
- 不删除 mermaid 图表（但删除关于图表的元信息注释）
- 不改变文章的整体结构顺序（可以合并冗余章节）
