# 本地 Markdown 分析工作流

## 元数据

- **类型**: Workflow
- **适用场景**: 对一批本地 markdown 文件进行全量阅读和分析，产出结构化报告
- **输出位置**: `contexts/daily_records/`
- **命名格式**: `{date}_local-analysis-{label}.md`

## 触发条件

- 用户提供本地目录或文件列表，说"分析这些文件"
- 需要跨文件提炼主题、洞察或演化轨迹

## 前提

- 明确分析范围（目录路径 / 文件列表 / 时间范围）
- 明确分析目标（自由指定：主题聚类、洞察提炼、时间线、对比、其他）

## 工作流程

### Step 1: 建立文件清单

```bash
find {target_dir} -name "*.md" | sort
```

记录文件总数和估计行数，作为 context 预算参考。

### Step 2: 分批读取

文件数 >20 时，启动并行 sub-agent 分批读取，每批 5-10 个文件，避免 context 溢出。

### Step 3: 分析并输出

根据用户指定的分析目标自由组织输出结构。没有固定维度要求。

常见输出类型（按需选择，不强制全部）：
- **Insights**: 非显而易见的结论、跨文件的隐含联系
- **Themes**: 主题聚类，标注关联文件和深度
- **Timeline**: 内容随时间的演化轨迹

### Step 4: 写入文件

写入 `contexts/daily_records/`，文件名加当前日期前缀。

## 注意事项

- 先建清单再读文件，避免超出 context
- 跨文件发现矛盾时，显式标注，不要自动解决
- 引用必须带文件名
