# T11. Cheap 是滞后指标，Hard 是领先指标

## 1. 核心公理

**"便宜"是 lagging indicator**，意味着过去二三十年文明工程投资的累积被压缩进一个 `pip install`。**"难"是 leading indicator**，意味着当前是工程前沿，未来二三十年的 `pip install` 会从这里诞生。

技术领域的 "hard" 和 "cheap" 不是稳定属性，是文明投资曲线的两端。**今天的 hard，就是 2040 年的 cheap。**

## 2. 深度推演

### 2.1 时序化的难度曲线

每一类基础能力都遵循相似的生命周期：

| 阶段 | 特征 | 谁能做 | 历史示例 |
|------|------|--------|---------|
| 前沿 | 博士论文级 | 10 个人 | Codd 1970 发表关系代数 |
| 框架 | 专家领域 | 1000 个人 | SQL 标准化 1980s |
| 标准 | 多数人可用 | 10 万个人 | MySQL/Postgres 1990s |
| 基础设施 | 不可见 | 所有开发者 | Rails ActiveRecord 2000s |
| 商品化 | 小时级搭建 | 非开发者 | 2020s CRUD no-code |

从前沿到商品化通常需要 30-50 年。整条曲线的意思是：**今天你看到的"便宜"，是 30-50 年前某个博士在黑板上的难题的终态。**

### 2.2 压缩复杂度的"化石燃料"比喻

当你用 Django 的 ORM 写 CRUD 时，你在消费什么？

- Codd 1970 年的关系代数（理论基础）
- 数十个数据库博士的查询优化算法
- MySQL、PostgreSQL 几十万行 C 代码
- ORM 抽象的几轮迭代（从 ActiveRecord 到 SQLAlchemy）
- 运维自动化、备份恢复、高可用方案的沉淀

**这一整条价值链被压缩进你的一个 `pip install django`。** 你在用几秒的时间消费 50 年的投资。

这和烧石油本质上是一样的——消费被压缩的过去。石油是亿万年光合作用的化石燃料，`pip install` 是几十年工程投资的化石燃料。

### 2.3 Hard 作为领先指标的含义

反过来，当你看到一个领域当前很 hard：

- 大量重复的基础设施重建（每家都在重新写 agent loop、permission layer、sandbox）
- 没有公认的接口标准
- 失败案例多于成功案例
- 人才稀缺、工资高
- 投资集中（VC 热钱涌入）

这些都是 **"还没到收敛点"** 的信号。而"还没到收敛点"恰好意味着 **未来 20-30 年的工程资源会往这里流**。

**推论**: 今天谁解决了这些 hard 问题，谁就定义了下一代的 `pip install` 长什么样。

### 2.4 Cheap 和 Hard 的价值非对称

**消费 Cheap 的边际价值递减**:
- CRUD 今天一个人 10 分钟搭完，明天会是 AI 1 秒搭完
- 今天的 CRUD 工程师已经在被替代
- 消费既有的抽象层，你在和所有能消费它的人竞争

**生产 Hard 的边际价值递增但波动大**:
- 你可能失败（大部分 agent 框架会死掉）
- 但成功就是定义一个时代的抽象层
- 投资回报高度非线性

### 2.5 为什么大多数人押错

**偏差**: 人眼睛容易被 "舒适的现状" 吸引。Cheap 的领域进入门槛低、工具成熟、教程齐全、职位密集——这些都是 lagging indicator，告诉你的是 **过去** 这里很有机会。

**正确的读法**: 把 Cheap 理解为 "这里已经拥挤了，先发优势已经被收割完了"。把 Hard 理解为 "这里正在形成，先发优势还没被收割"。

## 3. 应用判定

### 3.1 何时使用

- **职业方向选择**: 你想做未来 20 年还有价值的事，还是未来 5 年就会被 AI/自动化消灭的事？
- **技术投资决策**: 公司资源投在哪里？"把现有技术用得更好" vs "在前沿难题上下注"
- **判断 hype**: 看到新技术时，问"它是在消费现有复杂度（cheap 的再包装），还是在生产新复杂度（hard 的前沿）"
- **个人学习投资**: 学一个工具 vs 学一个原理。工具会变 cheap，原理是 hard 的来源

### 3.2 如何识别 Hard 的领域

当前指标（2026 年的 AI / Agent 领域）：

| 信号 | 含义 |
|------|------|
| 每家都在重建同样的东西 | 还没有标准，前沿 |
| 没有公认 benchmark | 问题定义还在争议中 |
| 失败案例 > 成功案例 | 真的难 |
| 术语还在漂移 | 学科还在形成 |
| "Best practice" 每半年换一次 | 没有收敛 |
| 顶级公司都在内部重建 | 外部没有足够好的方案 |

2026 年的 hard 领域（示例）：
- Agent observability（多 agent 失败调试）
- Long-horizon agent reliability
- Harness engineering for production agents
- Evaluation as measurement system
- AI system cost/latency/rollback operations（下一代 SRE）

### 3.3 如何在 Hard 领域下注

1. **选一个 hard 领域深耕 3-5 年。** 不要追着 hype 切换——每次切换都在消费你的积累。
2. **接受产出不确定性。** Hard 的定义就是失败率高。每次尝试都是在收集 "什么行 / 什么不行" 的信号。
3. **记录你的认知演化。** 当这个领域收敛时，最早把它理清楚的人会是定义者。你的笔记就是你的护城河。
4. **不要被 "还没市场" 吓到。** Hard 领域没有现成市场——等有市场时你已经晚了。

### 3.4 如何避免押在正在消失的 Cheap 上

- 问自己：这个技能/工具，5 年后还会需要人专门做吗？
- 问自己：这个技能的核心是 "懂得用某个工具" 还是 "理解某个原理"？工具会被替代，原理不会
- 问自己：我在做的事情，是 "消费过去的抽象" 还是 "构建未来的抽象"？

## 4. 常见陷阱

### 4.1 "现在这个领域很热，赶紧入场"

"热" 通常是 lagging indicator。真正的 hard 领域在热之前就已经存在，但外人看不到。等它 "热" 了，意味着收敛阶段开始，先发优势已经被收割。

### 4.2 "这个东西太底层了，没市场"

今天 Postgres 的 core committer 也 "没直接市场"。但他们的工作托起了万亿美元的行业。 "没市场" 往往只是 "市场还没显化"——等它显化时，你已经是定义者。

### 4.3 "Hard 的东西太冒险，我做 Cheap 的稳一点"

稳的错觉。Cheap 领域的 "稳" 是因为在既有抽象层之上，但 **抽象层本身会被下一代抽象替代**。CRUD 程序员曾经很稳，今天正在被 AI 替代。真正的不稳，是押在一个会消失的抽象层上。

### 4.4 "等它成熟了我再进"

"成熟" = 收敛 = 先发优势已经被收割。你能进的时候，能定义规则的窗口已经关了。你只能做规则的使用者。

## 5. 实践案例

### 5.1 SRE 这个职业的形成

- 2003 年 Google 内部，很少人做这件事，没名字，没标准
- 2010s 出书、开课、标准化
- 2020s 变成所有公司的标配，薪资中位数
- 2030s? 会不会被 AI-driven ops 替代？

谁在 2003 定义了 SRE，谁在 2020s 拿到了最大回报。晚一点进都只能做执行者。

### 5.2 AI / Agent 时代的对偶

- Harness engineering 今天 hard（每家重建）
- Multi-agent orchestration 今天 hard（没收敛）
- AI cost/latency/rollback ops 今天 hard（下一代 SRE）

10 年后这些会变成 `pip install`。今天在这里做对的人，会是 10 年后的 "发明了 SRE 那群人"。

### 5.3 反例：学 LangChain 没学透原理

LangChain 2023 年很热。到 2026 年 LangChain 1.0 已经大幅简化，"极度中立、抛弃过度功能堆砌"。只学了 LangChain API 的人，现在技能快速贬值。但学了 "agent loop 原理 + context engineering 原理" 的人，能把这个理解迁移到下一代任何框架。

**原理是 hard，框架是 cheap。押原理，不押框架。**

## 6. 与其他公理的关联

- **T10 反向耦合定律** —— T10 解释 "为什么难"，T11 解释 "难的战略价值"。两者是互补的一对
- **T05 认知是资产，代码是消耗品** —— 认知是 hard 的积累，代码是 cheap 的消费
- **T01 基础设施优于组件** —— 押基础设施 = 押 hard；押组件 = 押 cheap
- **A09 构建者思维是护城河** —— 构建者在生产 hard，使用者在消费 cheap
- **A13 技术采用三阶段** —— 技术采用曲线和 cheap/hard 曲线是同一个现象的不同切面

## 7. 结论

**"Cheap" 是过去投资的滞后指标，告诉你那里曾经是前沿。"Hard" 是未来投资的领先指标，告诉你那里正在形成下一代基础设施。**

大多数人把 cheap 当成 "机会" 进入，把 hard 当成 "风险" 规避。这是反的。**cheap 意味着机会的窗口正在关闭，hard 意味着窗口正在打开。**

个人、团队、公司的长期价值，取决于押对曲线的那一端。消费过去，还是生产未来，是每一次资源分配都在做的选择。
