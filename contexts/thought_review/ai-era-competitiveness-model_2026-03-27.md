# AI 时代竞争力：稀缺性迁移模型

**Date:** 2026-03-27
**Source:** ChatGPT 对话分析 + 多轮深度讨论
**Status:** 框架成型，可用于面试叙事

---

## Key Insights

- **假亮区比暗区危险。** Agent 的主要失败模式不是"不知道"（暗区，RAG 可解），而是"训练数据里有类似案例导致自信地错"（假亮区）。后者不触发不确定性信号，监控看不出来。解法是在假亮区附近插强制人工确认点，不是让模型更聪明。

- **评估和执行的成本关系反转了。** 传统软件：写代码贵，验证便宜（跑测试）。AI 系统：生成代码便宜，判断输出是否真正解决问题变贵了。evaluation design 正在成为和 system design 同等重要的工程学科。

- **翻译是多层的，AI 只打平了中间层。** 编译器解决了代码到 binary（最底层），大模型解决了模糊需求到结构化代码（中间层），从混乱现实到清晰问题定义（最上层）仍然是人的工作。川普身边的翻译翻的不是语言，是政治语境。

- **不存在收敛到一个点的终极解。** 重要问题的最优解取决于当时的规模、约束和取舍，这些条件持续在变。答案是被选择出来的，不是被计算出来的。Douglas Adams 1979 年就说清楚了：42。

- **Jevons Paradox 适用于 coding，但有时间差。** Coding 变便宜 → 需求总量井喷，但短期企业先"省人"再"扩需求"，中间有过渡期错配。个人策略：不等组织想明白，自己先跑到需求定义层。

## Open Questions

- 假亮区的检测：除了 HITL，有没有系统性的方法识别模型何时处于假亮区？confidence calibration 在垂直场景下的实际效果如何？
- evaluation design 作为工程学科的方法论还不成熟。当前 eval 实践大多是 benchmark + vibe check，缺乏等价于传统 testing 的严格框架。
- Jevons Paradox 的过渡期具体有多长？哪些行业/场景会先完成从"省人"到"扩需求"的转变？
- 需求定义能力本身能不能被 AI 部分解决？（AI 辅助 PM 做需求拆解、用户调研分析）如果能，稀缺性会继续往哪一层迁移？

## Concrete Artifacts

### 四层主题树

```
L0 — AI 压缩执行层，稀缺性向上迁移
L1 — 底层机制
  ├─ 翻译层模型：机械层先被自动化，判断层留下
  └─ 问题性质：可压缩（模式匹配）vs 不可压缩（情境判断）
L2 — 工程影响
  ├─ 评估 > 执行
  ├─ 假亮区 > 暗区（失败模式优先级）
  └─ 约束设计取代逻辑编写
L3 — 市场影响
  ├─ Jevons Paradox → 需求井喷
  ├─ 过渡期错配
  └─ 问题定义成为新瓶颈
L4 — 个人策略
  ├─ 往上走（执行层 → 定义层）
  ├─ 建立评估能力
  └─ SRE 思维迁移（不确定性管理 + 语义可观测性）
```

### 面试三段论

**定位问题：** Agent 当前最大挑战是可靠性，不是能力。"跑通了"和"跑对了"之间的差距在垂直场景里尤其大。

**判断框架：** 失败模式分暗区（缺知识，RAG 可解）和假亮区（假自信，需 HITL）。假亮区更危险因为不触发告警。

**独特视角：** SRE 背景让我把 agent 可靠性看成基础设施问题。Agent 需要语义层可观测性（决策点、输入依赖、置信度分布），不只是系统层 metrics。evaluation design 之于 agent = monitoring design 之于传统 infra。
