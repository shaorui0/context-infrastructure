Beyond Nano Banana Pro

Slide 生成方案选型 · 2026-05-21

当你没有 Gemini API key，Clean Ink 风格的 deck 该怎么做？

本 deck 回答这个问题：从工具链、成本、迭代速度三个角度，比较两条可行路径，并给出推荐。

Intro1/12
这个 deck 来自 contexts/survey_sessions 里关于 slide 生成替代方案的调研。背景是没有 Gemini API key 之后，原来的 Nano Banana Pro 流水线整条停摆。我们用 12 张 slide 回答一个问题：Clean Ink 风格的 deck，除了图像生成 API，还有什么路？

起点：没 Gemini key

流水线整条停摆

没 API key 就走不通 v1 任何后续节点。

迭代慢 + 烧钱

一张图 15–30s 出图，每次微调都要付费重跑。

放大要再调一次

1K → 4K 不是免费 upscale，需要二次生成或第三方放大模型。

Problem2/12
原来的 v1 流水线是 prompt → Gemini → PNG → Reveal.js 四段式。Gemini 这一段没了之后，后面三段全部失效。除了 key 本身，更深层的问题是：图像生成 API 的迭代速度和成本天然不适合 12 张 deck 反复打磨的场景。这就是我们要换路径的起点。

两条路，优先 Path A

Path A — HTML/SVG + Playwright

  • $0/张 · 零 API 调用
  • ~200ms 迭代 · 改字立刻看到
  • 文字像素级完美 · 真字体非位图
  • CSS 强制全局风格统一

推荐路径

Path B — fal.ai 聚合 API

  • $0.03–0.09/张 · 多模型 fallback
  • 15–30s 出图 · 同步等待
  • 分辨率受限 · 通常 ≤2K
  • 跨 slide 风格容易漂移

备选 / 局部使用

Clean Ink 本质上是 line art + flat fills + sans-serif — 这正是 SVG 的母语。

Decision3/12
结论先行。两条路都能跑通，但 Path A 在你的具体场景下没有任何一个维度是输的。Path B 留作备选，比如某张 slide 真的需要摄影级插画。核心论点是最下面那句：Clean Ink 风格本身就是 SVG 原生能表达的东西，用图像生成 API 反而是用大锤砸钉子。

Clean Ink ≈ SVG 的语言

Clean Ink 特征 SVG/CSS 原生能力
冷浅灰底 + 极细网格linear-gradient()
海军蓝线条<path stroke> 默认
Flat color fillsfill="var(--teal)"
Sans-serif typographyfont-family
工程图纸感SVG 几何 + 1.5px strokes

左侧这张图本身就是用 SVG 画的 — 不用 Gemini，也能出工程蓝图感。

Path A4/12
这是说服力的核心一张。Clean Ink 风格的每一个视觉特征都能在 SVG/CSS 里找到一对一的原生表达。左边的齿轮 + 量角弧 + 标注线就是用纯 SVG 画的，没有任何位图。也就是说，用图像生成 API 来产出 Clean Ink，本质是让模型去模拟它本可以直接生成的代码。

Path A 工具链

  H --> R[Reveal.js 演示]

你已有的

  • Reveal.js（演示框架）
  • Playwright MCP（截图/导出）
  • chrome-devtools MCP（调试）
  • Claude Code（生成 HTML/SVG）

需要新增的

  • theme.css（约 10 分钟一次性写）
  • 各 slide 的 <section>（并行 subagent）
  • 0 个 API key
Path A5/12
工具链落地极轻：左边四个工具你都已经在用。右边唯一的新增成本是写一个 theme.css，大概十分钟，然后并行派 subagent 写各 slide。零 API key 是关键 — 没有外部依赖意味着这条流水线在任何机器、任何时段都能跑。

Path A vs Image-gen — 6 个维度

维度 Image-gen (v1) HTML+SVG (v2) 备注

迭代速度15–30s~200ms改字立即生效

在你的场景里没有任何维度是输的。

Path A6/12
六个维度逐个对齐。前五条 Path A 全胜，包括成本、速度、字体、一致性、可编辑性。第六条是 Image-gen 的强项 — 摄影级或绘画级插图 — 但 Clean Ink 风格本身就用不到这个能力。结论：选 Path A 没有任何代价。

Path B：何时仍然需要图像生成

摄影感封面

标题页 hero 图、产品 mockup 照片

绘画级插图

艺术海报、漫画式叙事 slide

真实人物/物品

需要拟真人像或具体商品的画面

即便如此，这些通常只占整个 deck 1–2 张；主体仍走 Path A。

Path B7/12
这一页定位 Path B 的合理使用边界。三类场景：摄影感封面、绘画级插图、真实人物或商品。强调即使要用，也只是点缀，不是主菜。Path A 的 HTML+SVG 仍然承担 90% 以上的 slide。

一把钥匙：fal.ai

单一 FAL_KEY，解锁 600+ 模型，比 Replicate 便宜 30–50%

模型强项分辨率价格/张
Seedream 4.5 Dense text rendering、最接近 Nano Banana Pro 2048×2048 $0.04
Recraft V3 长多行正文唯一可靠、品牌参考图 ~1K（需放大） $0.04 raster / $0.08 vector
Ideogram 3.0 Multi-line typography 鼻祖 ≤1536px $0.03 / $0.09
FLUX 1.1 Pro Ultra 真 4MP，文字密集场景偶错 4MP $0.06

排除：OpenAI gpt-image-1（≤1536px，做不出 crisp 1080p）

Path B8/12
fal.ai 是一站式聚合器，省去逐个注册各家 API 的麻烦。默认推 Seedream 4.5：2K 原生、文字密集场景接近 Nano Banana Pro。Recraft 适合长正文与矢量品牌图。OpenAI gpt-image-1 分辨率上限太低，直接排除。
